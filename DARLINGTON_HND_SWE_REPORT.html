1. Introduction

Background

According to the World Health Organization, approximately 2.2 billion people worldwide have a near or distance vision impairment. Web accessibility remains a significant challenge, with many websites not providing adequate support for assistive technologies or accessibility features. Accessibility Translator was conceived to address this gap by providing a comprehensive, user-friendly suite of accessibility tools.

The project draws on current research and industry practices to create a practical deliverable: a combined web application and browser extension that can be adopted by users without specialist training. It emphasizes client-side resilience so critical features continue to work offline or with intermittent connectivity.

Project Scope

This project encompasses a full-stack web application (PHP/MySQL + HTML5/CSS3/JavaScript), a Chrome Extension (Manifest V3) providing integrated browser-based accessibility, and advanced features including text-to-speech (TTS), optical character recognition (OCR), customizable color filters, and voice commands. The system also provides centralized preference storage and synchronization between devices.

Deliverables include: a public-facing settings UI, a robust preferences API, a background service worker for sync, and a well-documented extension package ready for distribution.

3. Literature Review

Accessibility Standards & Best Practices

The Web Content Accessibility Guidelines (WCAG 2.1) provide the baseline for this project. WCAG requires clear semantic structure, keyboard focus management, sufficient color contrast, and accessible form controls. The implementation follows these principles by exposing ARIA attributes, ensuring tab-based navigation, and providing text alternatives where necessary.

Related Technologies

Key technologies used include the Web Speech API for TTS and recognition, TensorFlow.js for client-side object detection (COCO-SSD), and Tesseract.js for OCR. These libraries enable processing to occur in the browser, reducing dependence on server-side compute and improving privacy.

4. System Overview & Analysis

Stakeholders

Primary stakeholders are end users with visual impairments or CVD, developers maintaining the system, and administrators responsible for user support. Requirements were gathered via stakeholder interviews, heuristic evaluations of existing tools, and a small user study with five participants to refine UX flows.

Current State vs Desired State

Before this project, users relied on a mix of desktop screen readers, browser add-ons, and OS-level accessibility features. The desired outcome is a unified, easily deployable solution that minimizes setup friction and centralizes preferences across devices and browser contexts.

Component Responsibilities

The extension popup offers quick controls; content scripts apply filters and extract text; the background service worker coordinates sync operations and routes messages; the web server provides persistent storage for preferences and authentication. Each layer is decoupled through message passing and well-defined APIs.

6. Implementation

Development Environment & Tooling

The project was developed using PHP 7.4+, MySQL, Apache (XAMPP), and modern JavaScript (ES6+). Development workflows used Git for source control and simple task scripts for linting and building extension assets.

Authentication & Preferences API

Authentication is handled server-side with bcrypt-hashed passwords. Session validation includes timeout checks and basic hijack mitigation. The preferences API accepts JSON payloads and stores preference documents per user; local storage and IndexedDB are used for immediate client-side persistence with background sync to the server.

Extension Internals

Core extension features include a PopupManager class for UI routing, an AccessibilityBubble injected into pages to present quick actions, and a safe messaging wrapper to avoid runtime exceptions if contexts are invalidated. Filters are applied via small injected stylesheets rather than heavy DOM rewrites to minimize rendering overhead.

5. Features

Text-to-Speech (TTS)

Browser-native speech synthesis with configurable voice, rate, and pitch. Supports reading pages, headers, links, or selected text. Quick action buttons in extension popup provide one-click access.

Color Filters

8 color filters including standard (grayscale, high-contrast, sepia) and color-blind variants (protanopia, deuteranopia, tritanopia). Filters apply instantly and persist across page navigation.

Voice Commands

30+ offline voice commands with fuzzy matching for typo tolerance. Web Speech API integration with Levenshtein distance-based scoring (â‰¥0.55 confidence threshold). Commands cover TTS control, filter management, navigation, and settings.

Object Detection & OCR

COCO-SSD model (TensorFlow.js) for real-time object detection. Tesseract.js for client-side OCR supporting multiple languages. Supports camera input and file upload with drag-and-drop.

9. Conclusions & Recommendations

Summary

Accessibility Translator successfully delivers a comprehensive accessibility suite combining robust authentication, browser-integrated features (TTS, filters, voice, OCR), offline capability, and WCAG compliance. The system is production-ready and serves as a solid foundation for future accessibility innovations.

Lessons Learned

  • Browser APIs vary significantly across browsers; thorough testing is essential
  • Accessibility tools must themselves be highly accessible
  • Offline-first design simplifies online synchronization
  • Fuzzy matching significantly improves user satisfaction

Future Recommendations

  • Add internationalization support (multiple languages)
  • Implement custom voice command creation UI
  • Expand to mobile platforms (iOS/Android)
  • Set up CI/CD pipeline (GitHub Actions)
  • Add community forum for user feedback
  • Create video tutorials for advanced features
